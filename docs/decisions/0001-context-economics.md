# ADR-0001: コンテキスト経済の実測と、そこから導いた方針

- Status: accepted (測定の一部を [ADR-0002](0002-roadmap.md) で訂正)
- Date: 2026-09-02

## 背景

Claude Code をレート制限下で使う。サブエージェント/並列はキャッシュのコールドスタート分だけ
損なので、メイン 1 本 + 引き継ぎで回す前提を置いた。では**何を最適化すべきか**を
想像ではなく実測で決めたい。

## 測定

`~/.claude/projects/*/*.jsonl` の過去 8 セッションを解析した (`agent stats` の元になった分析)。
加重は課金/レート制限の重み: `cache_read 0.1x / cache_write 2x(1h) / input 1x / output 5x`。

## 決定

1. ~~**最優先は Read の抑制** (79%)~~ → 優先度は ADR-0002 で引き下げ (実際は 11.8%)。
   ただし施策自体は有効なので維持する。同一ファイルの再読み込みを hook で deny し、
   mtime ベースにすることで Edit 後の正当な読み直しは自動的に通る。
2. **clear の閾値を 250k にする。** 再開コストは system + AGENTS.md + state.md ≒ 25k を
   2x で書き込み ≒ 50k 加重。500k → 50k に落とせば 1 ターンあたり 45k 加重の節約なので、
   ファイル読み直し分を見ても 3〜5 ターンで元が取れる。500k まで待つのは遅すぎる。
   → **`.agent/state.md` の本質的な役割は「clear を安くすること」**。
3. **キャッシュ残り時間をステータスラインに常時表示する。**
   ステータスラインはモデルのコンテキストに載らない (0 トークン) ので、監視はすべてここでやる。
4. **サブエージェントの損益分岐を明文化する。**
   `(メインに積むゴミ X − 返答 R) × (2 + 0.1 × 残ターン T) > 約 130k` のとき得。
   T=100 なら X > 約 13k、T=30 なら X > 約 28k。ただし X が 30k を超えるなら
   そもそも clear した方が安いので、実質「序盤の青天井探索」限定。
5. **安いモデルへの委譲を第一選択にする。** `opencode run` はヘッドレスで動作し、
   Claude のレート制限を一切消費しない。サブエージェントより厳密に安い。
6. **強制できるものは hook へ、hook にできないものだけ AGENTS.md へ。**
   AGENTS.md の 1 行は毎リクエスト課金されるうえ守られる保証がないが、hook は 0 トークンで必ず守られる。

## Why not

- **`agent test` を最優先にしなかった**: 実測で Bash は全体の 15.6%、テスト実行の最大出力も
  3,010 ch に過ぎなかった。ラッパの価値は「量」ではなく、モデルが毎回 grep パイプを発明する
  ことによる**分散とテール事故の抑制**にある。優先度は Read 対策の次。
  → **この判断の前提は誤りだった** (Bash はトークン基準で 44%)。ただし結論
  「ラッパの価値は量ではなく分散の抑制」は ADR-0002 の追測定でも支持された
  (ラッパが吸収できるのは Bash の 10.9% のみ)。
- **`agent ls` を作らなかった**: 実測上、ディレクトリ列挙由来の無駄は誤差だった。
  代わりに Read を減らす `agent outline` の方が効く (未実装)。
- **JSON 出力をデフォルトにしなかった**: 同じ情報で 30〜40% トークンが増えるため
  (波括弧・引用符・キー名の反復)。人間/LLM 向けは行形式、`--json` は機械用。
- **UserPromptSubmit での注入を使わなかった**: 毎ターン加算されるため。
  SessionStart なら先頭 1 回きりでキャッシュも壊さない。
- **要約のみで全文を捨てなかった**: 要約が肝心の 1 行を隠すとモデルが盲目デバッグに入り、
  かえってトークンを食う。全文は必ずディスクに退避し `agent log` で到達可能にする
  (「コンテキストは索引、ディスクが本体」)。

## 再検証

`agent stats` で同じ数字がいつでも出せる。施策の前後で回して効果を数値化すること。
